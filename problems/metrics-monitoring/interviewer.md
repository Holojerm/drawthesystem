# Interviewer notes (hidden)
Crux: a time-series-shaped store (columnar, chunked by time, tagged by labels) with write-path pre-aggregation at ingestion (not raw-point storage forever) is what makes both the write volume and long-range queries survive; alert evaluation runs as a separate streaming pass over the same ingested stream, not as repeated dashboard-style queries per rule.
Probes: how downsampling actually happens (roll up old high-res points into coarser buckets on a schedule, and query routes to whichever resolution fits the requested range); how the alert evaluator avoids re-paging for a still-firing condition (state machine: firing → paging once → resolved, not "check threshold, page if true" every tick); a monitoring-the-monitor answer for "how do you know THIS system is healthy."
Red flags: storing every raw data point forever with no downsampling plan; an alert rule that re-fires every evaluation cycle with no firing-state tracking (page spam); no answer at all for who watches the watcher.
