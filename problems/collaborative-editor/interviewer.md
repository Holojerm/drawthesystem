# Interviewer notes (hidden)
Crux: either Operational Transformation (transform each op against concurrent ops before applying, needs a central sequencing server) or a CRDT (each op is designed to commute/merge deterministically without a central authority) — either is acceptable if the candidate can explain why concurrent edits converge to the same result on every client either way; local edits apply optimistically on the typist's own client before round-tripping, which is what makes typing feel instant.
Probes: walk through two clients both inserting at the same cursor position concurrently — what does each end up with, and why do they converge; how a reconnecting client catches up without re-fetching the whole document (op log replay from a known version, or CRDT state sync); where the durable write happens without blocking the typing path (async persistence off the hot path, not synchronous per-keystroke).
Red flags: "last write wins" for concurrent edits in the same region (silently drops one person's keystrokes); no explanation of *why* the chosen merge approach converges, just naming OT or CRDT as a buzzword; synchronous disk write on every keystroke before acking the client.
