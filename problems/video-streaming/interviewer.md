# Interviewer notes (hidden)
Crux: split the upload into chunks and transcode them in parallel across a worker fleet (not one worker per whole video, which is what makes "a few minutes" possible for a 10-minute upload); adaptive bitrate via chunked segments at multiple resolutions/bitrates (HLS/DASH-style) with the client switching based on measured throughput, not the server guessing.
Probes: how chunked parallel transcoding reassembles into one seekable output; how the CDN handles a brand-new, suddenly-viral video with no cache history yet (origin shield / pre-warming vs. organic cache fill); what "adaptive" concretely means on the client (buffer-based ABR heuristics) versus just picking a fixed quality.
Red flags: transcoding a whole video serially on one machine ("it just takes a few minutes per minute of footage, that's fine"); no mention of chunked delivery — describing playback as one big file download; treating the CDN as a black box with no cold-start story for new content.
